# Stage 35 — Research Trajectory Memory\n\n## Purpose\n\nA research process cannot be represented adequately by its current state alone.\n\nStage 35 records the **trajectory**:\n\n```text\nstate₀\n  ↓\ntransition₁\n  ↓\nstate₁\n  ↓\nbranch\n  ├── hypothesis A\n  └── hypothesis B\n        ↓\n     test\n        ↓\n     failure\n        ↓\n     new constraint\n        ↓\n     state₂\n```\n\nThe history is part of the research information.\n\n## Why history matters\n\nThe same current hypothesis can have different meaning depending on how it was reached.\n\nA hypothesis that survived three explicit tests is not represented the same way as an identical hypothesis that has never been tested.\n\nConversely, a rejected branch remains useful because it records a constraint on the future search space.\n\n## Append-only rule\n\nPrevious states are never rewritten.\n\nIf a later interpretation changes our understanding of an earlier state, the system adds a new state and a `REVISES` or `REFERENCES` relation.\n\nIt does not rewrite history.\n\n## Reopening\n\nResearch is non-linear.\n\nA question abandoned at state 4 may become relevant again at state 11.\n\nThe system therefore creates a new state:\n\n```text\nstate₄\n  ...\nstate₁₁\n  ↓\nREOPEN\n  ↓\nstate₁₂\n```\n\nThe new state points to the old question. The old state remains intact.\n\n## Branches\n\nCompeting hypotheses are explicit branches.\n\nA branch may become:\n- ACTIVE\n- REJECTED\n- FALSIFIED\n- SUSPENDED\n- MERGED\n- ABANDONED\n\nA rejected branch is not deleted.\n\n## Architectural result\n\nThe system now preserves three dimensions:\n\n```text\nSEMANTIC STATE\n    what is known\n\nRESEARCH STATE\n    what is being investigated\n\nTRAJECTORY\n    how we arrived here\n```\n\nCombined with Stage 34:\n\n```text\nTRAJECTORY → CURRENT STATE → NEXT ADMISSIBLE ACTION\n```\n\nThe objective is not to force research into a linear workflow.\n\nThe objective is to make **continuity of thought machine-readable**.
