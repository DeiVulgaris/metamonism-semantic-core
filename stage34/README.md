# Stage 34 — Research Process Engine\n\n## Purpose\n\nStage 33 made the research process explicit. Stage 34 makes its **next transition computable**.\n\nThe engine does not answer a research question. It determines which research actions are admissible from the current state.\n\n## Principle\n\n```text\nCURRENT STATE\n    ↓\nBLOCKERS / OPEN QUESTIONS / TESTS / FAILURES\n    ↓\nADMISSIBLE TRANSITIONS\n    ↓\nNEXT RESEARCH ACTION\n```\n\nThe engine therefore operates on the **process**, not on the truth value of the hypothesis.\n\n## Transition priority\n\nThe current engine prefers:\n\n1. `DEFINE_BLOCKER`\n2. `ANALYZE_FAILURE`\n3. `RUN_TEST`\n4. `DESIGN_TEST`\n5. `REFINE_QUESTION`\n6. `REVIEW_STATE`\n\nPriority is operational, not epistemic. It does not mean that one hypothesis is more true than another.\n\n## Critical constraint\n\nThe engine produces:\n> **what should be investigated next**\n\nIt never produces:\n> **what the theory is**\n\nTherefore:\n\n```text\nengine output ≠ canonical semantic conclusion\n```\n\n## Example\n\nFor the R1-R4 research program, the current blockers include the state space, composition law, orientation/sign operator, and closure multiplicity.\n\nThe engine therefore does not jump to Dirac algebra. It returns the admissible transition:\n\n```text\nDEFINE_BLOCKER\n        ↓\ndefine state space / composition\n        ↓\nattempt explicit formalization\n        ↓\ntest correspondence\n```\n\nFor the frustration/surgery program, it similarly prevents the system from jumping directly from structural analogy to Planck-scale identification.\n\n## Architectural consequence\n\nThe semantic core now has three distinct functions:\n\n```text\nCANONICAL CORE\n    ↓\nwhat is established\n\nRESEARCH PROGRAM\n    ↓\nwhat is being investigated\n\nPROCESS ENGINE\n    ↓\nwhat may be done next\n```\n\nThis separation is essential.\n\nThe engine is not a theory generator. It is a **continuation mechanism**.
